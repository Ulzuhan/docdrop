# DocDrop: cierre del legado Node en la rama activa

Fecha: 08-09-2026. Alcance: limpieza del producto, sin nueva funcionalidad,
sin publicar imágenes, sin desplegar ni cambiar datos de producción.

## Arquitectura que queda

Go es el único backend. React/Vite compila desde src/ y se embebe en el binario.
Node/npm se conservan sólo en desarrollo, construcción y pruebas. next-themes
es una utilidad de React, no el framework Next ni un proceso de servidor.

Se retiran rutas Next, proxy e instrumentación, utilidades de servidor TypeScript,
Dockerfile.node, start.js, la preparación standalone y configuración específica
Next. Pantallas, estilos y fuentes pasan a src/screens y src/styles; no queda una
copia paralela de la interfaz. Iconos que vivían en src/app pasan a public/.
El código retirado sigue recuperable desde Git; la imagen publicada no se borra.

## Garantías conservadas

No cambia código funcional del backend Go, formatos JSON, milisegundos, contadores,
lápidas, usuarios, revocaciones ni permisos del volumen. La imagen sigue con uid
1001. No se restaura ningún almacén ni se crean dos escritores sobre el mismo.

Las antiguas unitarias OIDC se sustituyen por regresiones Go sobre configuración,
rutas públicas/internas del proveedor, PKCE, discovery, caché y errores. Los casos
de descarga ya los cubren las pruebas Go de rangos, cancelación, continuaciones,
blob ausente y reserva de plazas. Se añade expresamente la regresión de dos plazas
creadas en el mismo instante: soltar una no libera ni contabiliza la otra.
Las pruebas de colas de promesas del almacén Node dejan de aplicar: ese mecanismo
no existe en Go. Las unitarias del cifrado permanecen; se añaden dos de parámetros
HTTP entregados por Go al navegador.

## Herramientas e higiene

- npm run dev construye y arranca Go en loopback:13010 con .local/data; no hay
  servidor Next ni hot reload. La configuración OIDC debe exportarse explícitamente.
- npm run build construye assets y binario; los comandos HTTP usan Go por defecto.
- CI conserva los trabajos checks, go, imagen y compatibilidad. El primero valida
  React; no reconstruye un segundo backend. Se mantienen navegador sobre imagen
  final y compatibilidad contra el digest exacto, sin tocar aserciones.
- Tailwind escanea explícitamente src/ para no incorporar clases de documentos o
  artefactos viejos. El build Docker obtiene sus propios assets, no los del host.
- El instalador systemd instala /opt/docdrop/docdrop. No necesita Node en el host,
  conserva configuración y datos y deja de borrar recursivamente /opt/docdrop.
  Sólo se ha comprobado su sintaxis y ayuda; no se ha instalado en este servidor.
- Compose del producto lee .env y declara stop_grace_period: 10s. No se ha cambiado
  el compose productivo del repositorio de infraestructura.
- La limpieza de contenedores de pruebas se acota a la tirada propia; no elimina
  contenedores etiquetados de otros agentes. Credenciales y datos quedan excluidos
  de Git y del contexto Docker.
- Retirados next, @next y eslint-config-next del lockfile; actualizadas de forma
  dirigida browserslist, fast-uri y qs. npm audit: cero vulnerabilidades al comprobarlo.
- README reescrito para la arquitectura actual; contratos, despliegue, guía para
  agentes y plan alineados. El informe de auditoría anterior se marca histórico.

No se ha ejecutado una campaña de carga. Esto no sustituye un smoke autenticado
real ni acredita por sí solo la observación histórica de producción.
